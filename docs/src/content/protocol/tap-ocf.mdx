# Open Cap Table Format

The Open Cap Table Format ([OCF](https://www.opencaptablecoalition.com/)) is an open JSON standard for storing and sharing cap table data. TAP validates every record it stores offchain against OCF.

The schemas come from a git submodule at `ocf/`, pinned to commit `6d8c9322` of [transfer-agent-protocol/tap-ocf](https://github.com/transfer-agent-protocol/tap-ocf) (`ocf_version` `1.2.1-alpha+main`). Generated schema docs are in `ocf/docs/schema_markdown`.

## Terms

- **Issuer**: the company whose cap table is tracked.
- **Stakeholder**: a person or institution that holds equity on the cap table. OCF uses the word only for equity holders.
- **Security**: one block of equity, such as a stock issuance, identified by its `security_id`.
- **Transaction**: an event that changes the cap table, such as an issuance, transfer, or cancellation.

## What TAP covers

Only stock lives onchain: issuances, transfers, cancellations, retractions, reissues, repurchases, acceptances, and authorized-share adjustments. Equity compensation, convertibles, valuations, vesting terms, stock plans, and stock legends are MongoDB-only records. TAP has no routes for warrants, stock conversions, splits, consolidations, or stakeholder change events.

TAP sends a stakeholder's singular `current_relationship` onchain and stores it in MongoDB. On `main`, OCF's `current_relationships` array isn't stored; see [Known issues](/api-reference#known-issues). MongoDB records also carry TAP fields that aren't part of OCF, such as `issuer`, `tx_hash`, `is_onchain_synced`, `deployed_to`, and `deployed_by`.

## Onchain and offchain

| Concern | Onchain | OCF records in MongoDB |
| --- | --- | --- |
| Authority | The source of truth | A mirror, plus metadata |
| Ids | `bytes16` | Dashed UUID strings |
| Writes | The issuer's wallet or the server key | Metadata routes and the event poller |
| Recovery | Positions and transactions replay from contract events | Names, contact details, and MongoDB-only records exist only here, so back up MongoDB |

For the routes, see [API Guides](/api-guides). To rebuild a company in a fresh database, see [Register Issuer](/api-guides/issuer-management/register-issuer#bring-a-cap-table-into-a-fresh-database).
