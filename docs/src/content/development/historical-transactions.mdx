# Historical Transactions

`GET /historical-transactions/issuer-id/:issuerId` returns every stock issuance, transfer, cancellation, and other equity event recorded for a cap table.

## When rows appear

History comes from the event poller, not from the route or wallet that sent the transaction, so a confirmed transaction shows up after the poller's next pass, usually within about 20 seconds. `pnpm prod-poller` reads only finalized blocks, which adds about 20 minutes on Plume.

## Read the history

```bash
curl -s "$API/historical-transactions/issuer-id/$ISSUER_ID"
```

The response is an array of rows:

| Field | Meaning |
| --- | --- |
| `_id` | The history row's id. |
| `transactionType` | One of the types below. |
| `transaction` | The full transaction document, populated from its own collection. |
| `issuer` | The issuer id. |
| `tx_hash` | Hash of the onchain transaction, for explorer links. Older rows may have `null`. |
| `createdAt`, `updatedAt` | When the row was written to MongoDB. |

```json filename="Response"
[
  {
    "_id": "6719d3c1f1a2b3c4d5e6f701",
    "transactionType": "StockIssuance",
    "issuer": "<ISSUER_ID>",

    "transaction": {
      "_id": "56d14df5-6b04-7d93-1976-5e3f0d1703de",
      "object_type": "TX_STOCK_ISSUANCE",
      "security_id": "9a1b2c3d-4e5f-4a6b-8c7d-0e1f2a3b4c5d",
      "stakeholder_id": "<STAKEHOLDER_ID>",
      "stock_class_id": "<STOCK_CLASS_ID>",
      "quantity": "100000",
      "share_price": { "amount": "4.2", "currency": "USD" },
      "custom_id": "CS-001",
      "date": "2026-01-01",

```

The poller converts quantities and prices back to human values, so `"4.2"` is 4.20 per share. Authorized-share adjustment rows are the exception: they store `new_shares_authorized` as the raw ×1e10 value. See [Known issues](/api-reference#known-issues).

## Transaction types

| `transactionType` | Written for |
| --- | --- |
| `StockIssuance` | `issueStock`, plus every new security created by a transfer or by a partial cancel or repurchase |
| `StockTransfer` | `transferStock`, one row per security the transfer uses |
| `StockCancellation` | `cancelStock` |
| `StockRetraction` | `retractStockIssuance` |
| `StockReissuance` | `reissueStock` |
| `StockRepurchase` | `repurchaseStock` |
| `StockAcceptance` | `acceptStock` |
| `IssuerAuthorizedSharesAdjustment` | `adjustIssuerAuthorizedShares` |
| `StockClassAuthorizedSharesAdjustment` | `adjustStockClassAuthorizedShares` |

Creating a stakeholder or stock class adds no history row. The poller only marks the record `is_onchain_synced`.

## Sorting and pagination

Rows come back unsorted, with no pagination. `StockTransfer` documents have no `date`, so sort by `createdAt`, which follows the order the poller processed the events.
