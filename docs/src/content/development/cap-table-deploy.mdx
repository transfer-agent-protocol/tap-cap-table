# Create an Issuer

An issuer is the company whose cap table you track. Creating one deploys a new cap table contract through the factory and creates an issuer record. The issuer record is needed for every subsequent transaction.

## In the app

Issuers can deploy cap tables directly from the product app at `/app/mint`:

1. Open http://localhost:3000/app/mint and connect a wallet from the top bar.
2. Fill in the issuer details: legal name, formation date, country of formation, and authorized shares. Tax id, email, and address are optional.
3. Click **Create company**. The connected wallet calls `createCapTable` on the factory.
4. The issuer's wallet becomes the cap table's ADMIN. If `NEXT_PUBLIC_OPERATOR_ADDRESS` is set, that address also gets OPERATOR.
5. After the transaction confirms, the app registers the issuer with the server through `POST /issuer/register` and records your wallet as `deployed_by`.

In this flow, the issuer pays gas and owns their cap table. The server can also run [server-signed routes](/api-reference#server-signed-routes) on it if the server key's address is the operator address.

The company page URL, `/app/companies/<issuerId>`, contains the issuer id you use with the API.

## With the API

`POST /issuer/create` deploys the cap table with the server key and saves the issuer in one call. Before you start:

- Set a funded development key as `PRIVATE_KEY` in the root `.env`. That wallet pays gas and becomes the cap table's ADMIN.
- Register a factory in MongoDB: bootstrap with `REUSE_TAP_FACTORY=1`, or [deploy your own](/development/factory-deploy). Without one, the request fails with `Factory address not found`.

<Steps>

### Send a POST request

Using curl (or Postman), send a POST request to `/issuer/create`:

```bash
export API=http://localhost:8293

curl -s -X POST "$API/issuer/create" \
  -H "Content-Type: application/json" \
  -d @- <<JSON
{
  "legal_name": "Transfer Agent Protocol",
  "formation_date": "2022-08-23",
  "country_of_formation": "US",
  "country_subdivision_of_formation": "DE",
  "initial_shares_authorized": "10000000",
  "tax_ids": [{ "tax_id": "00-0000000", "country": "US" }],
  "email": { "email_address": "admin@example.com", "email_type": "BUSINESS" },
  "address": {
    "address_type": "LEGAL",
    "street_suite": "123 Main St, Suite 100",
    "city": "New York",
    "country_subdivision": "NY",
    "country": "US",
    "postal_code": "10001"
  },
  "comments": []
}
JSON
```

All fields are validated against the pinned [OCF schema](https://github.com/transfer-agent-protocol/tap-ocf).

### Check the response

The response includes your new issuer with key fields:

- **`_id`**: The issuer ID (you'll need this for all subsequent API calls)
- **`deployed_to`**: The cap table contract address onchain
- **`tx_hash`**: The deployment transaction hash

It will look like this, with your unique `_id`:

## Fields

| Field | Required | Notes |
| --- | --- | --- |
| `legal_name` | Yes | The issuer's full legal name. |
| `formation_date` | Yes | `YYYY-MM-DD`. |
| `country_of_formation` | Yes | ISO 3166-1 alpha-2 code, such as `US`. |
| `initial_shares_authorized` | Yes, for TAP | Whole shares as a string. OCF lets you omit it or send `UNLIMITED`, but TAP passes a number to `createCapTable`, which rejects 0. |
| `country_subdivision_of_formation` | No | ISO 3166-2 subdivision code, such as `DE` for Delaware. |
| `tax_ids`, `email`, `phone`, `address`, `dba`, `comments` | No | Stored with the issuer record. |
